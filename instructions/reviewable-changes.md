# Reviewable changes

Keep changes focused on the requested outcome and preserve unrelated work.
Update usage documentation with behavior changes and run checks appropriate
to the affected behavior. Report which checks ran and any material gaps.

When commits are requested, separate unrelated concerns. Explain the problem,
reason for the change, important tradeoffs, and actual validation in each
commit body. Use a concise subject, wrap body prose at 72 columns, and include
an accurate AI co-authorship trailer when an agent helped with the change.
Check the current HEAD before rewriting any commit and do not push without
an explicit request.
